# 보치아 라벨러 v2 화면 설계

2026-10-04 확정. 연구용 보치아 공 검출 데이터의 라벨링 앱 화면을 다시 설계한 문서입니다.
Codex가 같은 날 구현한 네이티브 라벨러([NATIVE_LABELER.md](../../NATIVE_LABELER.md))의 엔진과 저장 규칙은 유지하고, 화면과 조작을 이 문서대로 바꿉니다.

**1차 화면 교체까지 구현했습니다. 촬영 추가는 2차 계획입니다.** 시안은 HTML 프로토타입이고 실제 라벨에 저장하지 않습니다. 구현한 화면과 시안의 차이는 맨 아래 "1차 구현에서 달라진 점"에 있습니다.
구현 순서는 [PLAN.md](PLAN.md)에 있습니다. 1차는 화면 교체이고, 촬영 폴더 추가는 엔진 구조를 바꾸는 2차 계획으로 따로 씁니다.

## 데이터 준비

현장 PC에서 복사해 온 촬영 폴더를 추가하고, 자동 초안과 반복 장면 필터를 거쳐 검수 대상을 만듭니다.

- **촬영 표**: 가져온 폴더별로 묶습니다. 열은 촬영 시각과 길이, 프레임 수, 원본 상태(누락·손상), 자동 초안(완료 장수, 공 후보 수, 후보 없는 이미지 수), 반복 장면 필터(검수 대상, 보관), 검수 진행, 분할 배정입니다.
- **새 촬영 알림**: `data/imports` 아래에 추가되지 않은 촬영이 있으면 위쪽 알림으로 알려 줍니다. 다른 위치는 "촬영 폴더 추가"로 고릅니다.
- **추가 창**: 폴더 안의 촬영마다 촬영 완료 여부, 프레임 누락, 카메라 3대의 프레임 수 일치를 검사해 보여 줍니다. 문제가 있는 촬영은 기본으로 선택이 빠져 있습니다. 이미 추가된 촬영은 다시 추가할 수 없습니다.
- **추가 뒤**: 추가한 촬영만 자동 초안과 반복 장면 필터를 돌립니다. 진행률과 중단 버튼은 오른쪽 "최근 작업"에 나옵니다.
- **원본**: 읽기만 합니다. 복사, 수정, 삭제하지 않습니다.

## 검수와 편집

### 장면 목록

한 행은 카메라 3장을 묶은 장면입니다. 장면은 엔진의 규칙(수신 시각 차 20ms 이내, 프레임마다 한 번만 매칭)을 그대로 따릅니다.

- 행에는 컬러 카메라 썸네일, 프레임 번호와 시각, 카메라별 공 개수, 상태 점 3개(컬러 C, 모노 A, 모노 B)를 표시합니다.
- 점의 뜻은 초록 확인됨, 빈 원 미검수, 파랑 테두리 수정 중, 주황 보류, 짧은 줄 반복 장면(검수 제외)입니다.
- 카메라별 공 개수가 다르거나 자동 초안이 주의 표시를 남긴 장면에는 경고 아이콘을 붙입니다.
- 필터는 전체, 미검수, 보류, 확인됨이고 "반복 장면 숨김"이 기본으로 켜져 있습니다.
- 촬영별로 묶고 묶음 머리에 장면 수를 표시합니다.

### 석 장 보기

- 카메라 타일 3개를 C, A, B 순서로 나란히 둡니다. 타일 머리에는 숫자 키, 카메라 이름, 공 개수, 상태 칩이 있습니다.
- 전체 영상은 빠진 공을 찾는 용도입니다. 마스크를 옅게 채우고 공마다 번호를 붙입니다. 마우스를 올리면 그 주변을 4배로 키운 돋보기가 나옵니다.
- 영상 아래에 공마다 확대 조각을 둡니다. 조각은 공 박스의 긴 변의 2.1배 영역을 잘라 픽셀 그대로 키운 것이고, 윤곽선만 그립니다. 윤곽 확인은 여기서 합니다.
- 조각 격자의 빈 칸에는 "빠진 공 추가"를 두어, 누르면 그 카메라가 AI 분할 도구 상태로 열립니다.
- 매칭되는 영상이 없는 카메라는 빈 타일과 이유를 표시합니다.

### 제자리 확대

- 영상, 공, 조각을 클릭하거나 `1` `2` `3`을 누르면 그 카메라 타일이 같은 자리에서 커지고 나머지 둘은 폭 184의 작은 타일로 줄어듭니다. C, A, B 순서는 유지합니다.
- 공을 선택하면 그 공이 화면 높이의 약 34%를 차지하도록 자동으로 확대합니다. 확대율이 5배 이상이면 원본 픽셀 격자를 그립니다.
- 큰 타일에는 세로 도구 막대, 도구 설명 줄, 확대율, 전체 영상 미니맵을 올립니다.
- `Esc`는 미확정 제안 취소, 선택 해제, 석 장 보기 복귀 순서로 동작합니다.

### 편집 조작

마우스 규칙은 하나입니다. **왼쪽 버튼은 추가, 오른쪽 버튼은 제거**입니다. 터치패드를 위해 `Shift`+왼쪽 클릭도 제거로 받습니다.

| 하려는 일 | 조작 |
| --- | --- |
| 공을 하나씩 확대해 훑기 | `Tab`, `Shift`+`Tab`. 세 카메라의 공을 차례로 선택 |
| 윤곽 고치기 | `S` 후 공 안을 왼쪽 클릭, 넘친 곳을 오른쪽 클릭, `Enter` 반영 |
| 빠진 공 추가 | `S` 후 공을 클릭하거나 끌어서 박스 지정, `Enter` 반영 |
| 손으로 칠하기 | `B` 후 왼쪽 버튼으로 칠하고 오른쪽 버튼으로 지우기. `[` `]`로 굵기 |
| 둘레 직접 찍기 | `P` 후 꼭짓점 클릭, `Enter`로 닫기 |
| 마스크 없이 박스만 | `R` 후 끌기 |
| 박스 경계 1픽셀 | 방향키는 그 방향 경계를 바깥으로, `Shift`+방향키는 안으로 |
| 공 삭제, 일부 가림 | `Del`, `O` |
| 되돌리기 | `Ctrl`+`Z` |
| 보기 | 휠 확대, 빈 곳을 끌어 이동, `F` 화면 맞춤, `Z` 선택한 공으로, `M` 마스크 채움, `X` 박스 표시 |
| 장면 이동 | `A` 이전, `D` 다음, `N` 다음 미검수 |

지금 앱과 달라지는 키는 브러시(`R`에서 `B`), 박스(`B`에서 `R`), 장면 이동(방향키에서 `A` `D`)입니다. 방향키를 박스 보정에 쓰기 위해서입니다.

### 박스 보정

- 엔진의 규칙을 그대로 씁니다. `bbox`는 마스크 외곽 박스이고, 보정한 값은 `detection_bbox`로 따로 저장합니다. 마스크는 바뀌지 않습니다.
- 오른쪽 패널에 경계별 −, + 버튼과 보정값, X·Y·W·H를 표시합니다. 한 경계를 움직이면 반대 경계는 고정입니다.
- 이미지 밖으로 나가거나 폭·높이가 1픽셀보다 작아지는 조작은 막습니다.
- 보정한 박스는 흰 실선, 마스크 외곽은 청록 점선으로 함께 그립니다. "마스크에 맞춤"으로 보정을 지웁니다.
- 윤곽을 새로 만들거나 고치면 보정값은 지워집니다.

### 확인 상태

이미지마다 미검수, 확인됨, 보류 중 하나입니다. 사람이 고쳤지만 아직 확인하지 않은 이미지는 수정 중으로 표시합니다.

| 조작 | 동작 |
| --- | --- |
| `E` | 장면의 검수 대상 이미지를 모두 확인됨으로 바꾸고 다음 미검수 장면으로 이동 |
| 상태 칩 클릭, `Shift`+`E` | 그 카메라 한 장만 확인됨으로 전환 |
| `Q` | 초점 카메라가 있으면 그 한 장을, 없으면 장면의 미검수 이미지를 보류로 바꾸고 다음 미검수 장면으로 이동 |
| 확인한 이미지를 수정 | 그 이미지만 수정 중으로 돌아감 |

공이 없는 이미지도 같은 방식으로 확인합니다. 미확정 제안이 있거나 저장에 실패하면 확인과 장면 이동을 막습니다.

### 오른쪽 패널

- **이 장면의 공**: 카메라별로 묶은 공 목록. 크기, 출처(SAM, 추적, 수동), 수정됨·가림 표시, 숨기기와 삭제.
- **선택한 공**: 일부 가림, 색상(컬러 카메라만, 선택 사항), 박스 보정. 선택한 공이 없으면 카메라별 공 개수와 상태를 요약합니다.
- **확인**: "세 장 확인하고 다음 장면", 보류, 다음 미검수.

## 분할

엔진의 규칙을 그대로 씁니다. 검수 대상을 모두 확인해야 확정할 수 있고, 촬영 단위로 나누며, 같은 배치로 묶은 촬영은 함께 움직입니다. 목표는 80/10/10입니다.

- **비율 막대**: 이미지 기준 실제 비율과 목표 위치를 함께 표시합니다. 아래에 쪽별 촬영 수, 이미지 수, 공 수, 공 없는 이미지 수를 씁니다.
- **촬영 표**: 확인한 이미지와 장면 수, 공 수, 공 없는 이미지 수, 작은 공(32픽셀 미만) 수, 같은 배치 묶음, 배정 버튼(학습·검증·평가).
- **점검**: 같은 촬영이 두 쪽에 걸치는지, 세 쪽에 모두 이미지가 있는지, 공 없는 이미지가 빠진 쪽이 있는지, 촬영이 1개뿐인 쪽이 있는지, 모든 촬영이 같은 날인지를 자동으로 표시합니다.
- **확정**: 배정과 라벨 상태를 데이터 버전으로 기록합니다. 확정 뒤 라벨을 고치면 다시 확정해야 내보낼 수 있습니다. 평가에 넣은 촬영은 첫 학습 뒤에는 바꾸지 않습니다.
- **검수가 끝나지 않았을 때**: 배분안은 미리 볼 수 있지만 확정 버튼은 남은 장수와 함께 막아 둡니다.

## 내보내기

| 형식 | 박스 | 파일 | 대상 |
| --- | --- | --- | --- |
| YOLO 검출 라벨 | 보정한 검출 박스 | `labels/{train,val,test}/*.txt`, `data.yaml` | YOLO26 |
| COCO 검출 | 보정한 검출 박스 | `annotations/instances_detection_{train,val,test}.json` | D-FINE-S, RT-DETRv2-S, Faster R-CNN |
| COCO 마스크 | 마스크와 마스크 외곽 박스 | `annotations/instances_{train,val,test}.json` | 분할 실험용 |
| 공 조각 이미지 | 검출 박스로 자름 | `crops/{train,val,test}/*.png` | 분류 실험용, 선택 사항 |

- YOLO 검출 라벨, COCO 검출, COCO 마스크는 항상 만듭니다. 고를 수 있는 것은 공 조각 이미지뿐입니다.
- 원본 이미지와 `manifest.json`은 항상 포함합니다. 화면 밝기와 오버레이는 이미지에 들어가지 않습니다.
- 데이터 버전, 쪽별 이미지·공 수, 저장 위치, 예상 크기를 보여 줍니다.
- 오른쪽에 YOLO26 학습 명령 복사, 내보내기 기록, 비교 원칙을 둡니다.

## 엔진에서 바꿀 것

분할과 내보내기는 화면만 바꿉니다. 아래 항목만 엔진 변경이 필요합니다. 위 여섯 줄(촬영 ID부터 폴더 추가까지)은 2차 계획이고, 아래 네 줄은 1차 계획에 들어 있습니다.

| 항목 | 지금 | 바꿀 내용 |
| --- | --- | --- |
| 촬영 ID | 입력 폴더 기준 상대 경로의 해시 | `session.json`과 `frames.jsonl` 내용의 해시. 폴더를 옮겨도 같은 촬영 |
| 원본 서명 | 프로젝트 전체에 하나. 촬영을 추가하면 프로젝트가 열리지 않음 | 촬영마다 따로 저장. 추가해도 기존 라벨 유지 |
| 원본을 못 찾을 때 | 프로젝트를 열지 못함 | 그 묶음만 "원본을 찾을 수 없음"으로 표시하고 위치를 다시 지정 |
| 기존 프로젝트 | 경로 기반 ID | 한 번 변환. 변환 전 파일은 보관 |
| 자동 초안의 공 후보 | 2026-10-02용 캐시 파일 경로가 코드에 고정 | 자동 초안 작업이 촬영 폴더의 `calibration.json`으로 후보 찾기부터 수행 |
| 폴더 추가 | 시작 옵션으로만 지정 | 추가 창의 검사와 등록 |
| 목록 썸네일 | 없음 | 128×96 썸네일을 만들어 엔진 메모리에 보관 |
| 촬영별 통계 | 이미지 수만 | 공 수, 공 없는 이미지 수, 작은 공 수 |
| AI 분할의 박스 지정 | 점만 받음 | 끌어서 지정한 박스도 받음 |
| 내보내기 기록 | 없음 | 내보낸 폴더, 데이터 버전, 시각 목록 |

## 구현 방식

Dear ImGui 화면과 Python 엔진(localhost)을 유지합니다. 화면과 작업 흐름이 있는 `src/native_labeler_app.cpp`의 그리기 코드를 이 설계로 바꾸고, 통신·저장·마스크 모델은 그대로 씁니다.

1. **테마와 뼈대**: 글꼴, 색, 아이콘, 위쪽 단계 표시, 상태 막대.
2. **검수와 편집**: 장면 목록, 석 장 보기와 공 조각, 제자리 확대, 오른쪽 패널, 새 조작.
3. **분할과 내보내기**: 비율 막대, 점검, 형식 표.
4. **데이터 준비와 촬영 추가**: 위 표의 엔진 변경.
5. **속도**: 2026-10-04 측정으로 엔진에서 이미지 1장을 받는 데 약 0.1초, 장면 하나에 약 0.3초입니다. 다음 장면을 미리 읽고, 부족하면 C++에서 원본을 직접 읽습니다.

## 오류 처리

지금 구현의 안전장치를 유지합니다.

- 저장에 실패하면 장면 이동을 막고 복구 파일을 남깁니다.
- 미확정 제안이 있으면 확인과 이동을 막고 반영 또는 취소를 안내합니다.
- 늦게 도착한 추론 결과는 장면, 공, 편집 버전을 대조해 버립니다.
- 라벨이나 검수 대상이 바뀌면 분할 확정이 풀립니다.

새로 추가하는 처리입니다.

- 원본 폴더를 찾지 못한 촬영은 목록에 남기되 열 수 없게 하고, 위치 다시 지정을 안내합니다.
- 추가 창에서 미완료 촬영이나 카메라 프레임 수가 맞지 않는 촬영은 이유를 표시하고 기본으로 제외합니다.
- 다른 카메라의 좌표를 복사하지 않습니다.
